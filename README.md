# TCP Chat Server

Многопоточный TCP-чат на Go с поддержкой нескольких одновременно подключённых клиентов.

Проект создан как практическая работа для изучения Go backend-разработки, конкурентности, TCP-соединений, goroutine, channels, context и graceful shutdown.

## Возможности

* одновременная работа нескольких TCP-клиентов;
* обработка каждого клиента в отдельной goroutine;
* централизованный Hub для управления подключениями и сообщениями;
* обмен данными между goroutine через channels;
* graceful shutdown;
* ограничение количества одновременных подключений;
* хранение истории сообщений в памяти;
* команды для работы с чатом;
* HTTP endpoints для мониторинга;
* сбор статистики сервера;
* настройка параметров через аргументы командной строки;
* таймаут неактивных TCP-соединений.

## Архитектура

Основой приложения является `Hub`.

Для каждого TCP-клиента создаётся отдельная goroutine. Hub отвечает за управление подключёнными клиентами, регистрацию и отключение, рассылку сообщений и обработку запросов.

Упрощённо архитектура выглядит так:

```text
                    ┌─────────────────┐
                    │   TCP Client    │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ HandleClient()  │
                    │    goroutine    │
                    └────────┬────────┘
                             │
                         channels
                             │
                             ▼
                    ┌─────────────────┐
                    │      Hub        │
                    │                 │
                    │  register       │
                    │  unregister     │
                    │  broadcast      │
                    │  requests       │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
          Client #1       Client #2      Client #3
```

Hub централизованно управляет состоянием подключённых клиентов, поэтому доступ к основной `clients` map не разносится по разным goroutine.

## Требования

Для запуска проекта потребуется:

* Go;
* любой TCP-клиент, например `telnet` или `netcat`.

## Запуск

Клонировать репозиторий:

```bash
git clone https://github.com/ichuvilin/tcp-chat.git
cd tcp-chat
```

Запустить проект:

```bash
go run ./cmd/server
```

Или собрать бинарный файл:

```bash
go build -o tcp-chat ./cmd/server
```

После сборки:

```bash
./tcp-chat
```

В Windows:

```powershell
.\tcp-chat.exe
```

При запуске сервер выводит основные параметры конфигурации.

## Конфигурация

Параметры сервера можно передавать через аргументы командной строки. В текущей реализации доступны следующие параметры:

| Параметр         | По умолчанию | Описание                           |
| ---------------- | -----------: | ---------------------------------- |
| `--port`         |       `8080` | TCP-порт сервера                   |
| `--max-conn`     |         `50` | Максимальное количество соединений |
| `--log-level`    |       `info` | Уровень логирования                |
| `--history-size` |         `50` | Размер истории сообщений           |

Пример:

```bash
go run ./cmd/server \
  --port 8080 \
  --max-conn 100 \
  --log-level info \
  --history-size 100
```

## Подключение к серверу

### Telnet

```bash
telnet localhost 8080
```

### Netcat

```bash
nc localhost 8080
```

Можно открыть несколько терминалов и подключить несколько клиентов одновременно.

Например:

```text
Клиент 1: Привет!
Клиент 2: Привет от второго клиента!
Клиент 3: Всем привет!
```

Сообщение отправляется всем подключённым клиентам, кроме отправителя.

| -------- | ------------------------------------------ |
| `/help`  | Показать список доступных команд           |

## HTTP-мониторинг

Помимо TCP-сервера приложение запускает HTTP-сервер для мониторинга.

HTTP API используется для получения состояния и статистики сервера.

### Health Check

```http
GET /health
```

Пример:

```bash
curl http://localhost:9090/health
```

Пример ответа:

```json
{
  "status": "healthy",
  "active_connections": 2,
  "uptime_seconds": 184
}
```

### Статистика

```http
GET /stats
```

Пример:

```bash
curl http://localhost:9090/stats
```

В статистике можно получить информацию о:

* количестве активных соединений;
* количестве обработанных сообщений;
* количестве ошибок;
* времени работы сервера.

## Graceful Shutdown

При получении сигнала завершения сервер выполняет корректное завершение работы.

Основные этапы:

1. прекращается приём новых TCP-соединений;
2. подключённым клиентам отправляется сообщение о завершении сервера;
3. активные чтения клиентов прерываются;
4. сервер ждёт завершения клиентских goroutine;
5. завершается работа Hub;
6. освобождаются сетевые ресурсы.

Для контроля завершения используются `context.Context` и `sync.WaitGroup`.

## Конкурентность

Одна из основных целей проекта — практическое изучение конкурентности в Go.

В проекте используются:

* goroutines для обработки клиентов;
* channels для обмена данными между goroutine;
* `select` для ожидания нескольких событий;
* `context.Context` для отмены операций;
* `sync.WaitGroup` для ожидания завершения goroutine;
* atomic operations для потокобезопасной работы со статистикой;
* TCP deadlines для контроля неактивных соединений.

Основная идея архитектуры заключается в том, что Hub централизованно обрабатывает события, связанные с клиентами и сообщениями.

## История сообщений

История сообщений хранится непосредственно в памяти процесса.

Для неё используется циклический буфер фиксированного размера.

Это позволяет:

* ограничивать потребление памяти;
* не создавать постоянно растущий список сообщений;
* получать последние сообщения без хранения всей истории.

Размер истории можно изменить:

```bash
go run ./cmd/server --history-size 100
```

## Статистика сервера

Во время работы сервер собирает статистику:

```text
Active Connections
Total Messages Processed
Error Count
Uptime
```

Для счётчиков используется `sync/atomic`, а uptime рассчитывается относительно времени запуска сервера.

## Проверка race conditions

Для проверки конкурентного кода можно использовать встроенный race detector Go:

```bash
go run -race ./cmd/server
```

Также можно собрать бинарный файл с race detector:

```bash
go build -race -o tcp-chat ./cmd/server
```

Это позволяет обнаруживать конкурентный доступ к общей памяти во время работы программы.
